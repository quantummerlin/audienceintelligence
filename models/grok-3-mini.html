What Grok 3 Mini Was

Grok 3 Mini was xAI's lightweight reasoning entry — designed for logic-based tasks that don't require deep domain knowledge. It was the counterpart to Grok 3 (the full flagship), offering visible thinking traces at roughly one quarter the cost. The model had a 131,072-token context window, function calling support, and structured output support. At $0.30/$0.50/1M, it was competitive with DeepSeek R1's budget tiers and sat squarely in the bc-cheap tier.

The model was text-to-text only — no image input, no audio, no file ingestion. Its value proposition was narrow and deliberate: cheap reasoning. Teams that needed visible chain-of-thought at low cost could route logic tasks, math problems, and structured analysis to Grok 3 Mini while reserving heavier flagships for generation-intensive workloads.

The Budget Reasoning Niche

In early-to-mid 2026, reasoning-capable models were split into two clear price bands: expensive flagships at $1.00/1M or more, and budget reasoning models priced between $0.30–$0.50/1M. Grok 3 Mini held a strong position in the second band, alongside Qwen3 variants, DeepSeek V4 Flash, and Gemini Flash Lite. Teams that needed visible chain-of-thought at low cost had real, production-grade options.

The case for Grok 3 Mini over non-reasoning budget models was straightforward: for logic-heavy workloads — math validation, code review, structured analysis — you pay a small premium over a pure generation model and get traceable reasoning in return. At $0.30 input and $0.50 output, the reasoning tax felt reasonable.

What Happened

In May 2026, xAI deprecated Grok 3 Mini on OpenRouter. The x-ai/grok-3-mini slug now returns HTTP 404 with the message:

OpenRouter Error — HTTP 404

"Grok 3 Mini is deprecated. xAI recommends switching to Grok 4.3 (https://openrouter.ai/x-ai/grok-4.3)"

On xAI's own API, the grok-3-mini model name is now an alias for Grok 4.3 — meaning calls using that hardcoded name are silently routed to the $1.25/$2.50/1M flagship. For teams using xAI's API directly with model names in config files or environment variables, this constitutes a silent price increase of 4x or more. No API-level error is thrown; billing just gets larger.

Migration Options

The right replacement depends on what you were using Grok 3 Mini for. If reasoning traces were essential, the path narrows. If budget was the primary constraint, several alternatives undercut even Grok 3 Mini's historical pricing.

  • 01
    Grok 4.3 — xAI's official recommendation. Better reasoning capability, 1M context window (vs 128K), and three reasoning depth levels (low / medium / high). Use reasoning_effort: "low" to approximate Grok 3 Mini's lightweight trace depth at the lowest cost tier. Still 4x more expensive at $1.25/$2.50/1M, but xAI's only in-family reasoning option now that Grok 3 Mini is gone. OpenRouter: x-ai/grok-4.3.
  • 02
    DeepSeek V4 Flash (free) — $0.00/1M on OpenRouter's free tier, with visible reasoning. If cost is the primary concern and you can tolerate the rate limits and latency of the free tier, this is the lowest-cost reasoning option available. Benchmark tier: bc-free. Caveats: free tier has stricter rate limits and is not suitable for high-throughput production workloads.
  • 03
    Gemini 3.1 Flash Lite — $0.25/$1.50/1M, ultra-fast, no visible reasoning chain but excellent throughput and strong instruction following. Best choice if you were using Grok 3 Mini for structured generation tasks (function calling, JSON outputs) rather than true reasoning traces. Output pricing is 3x Grok 3 Mini's historical rate but significantly cheaper than Grok 4.3.
  • 04
    Qwen3.6 27B — $0.325/$3.25/1M with visible reasoning chain. Mid-tier capability and the closest pricing match to Grok 3 Mini on the input side. Output is more expensive ($3.25 vs $0.50) but reasoning traces are visible and the context window is competitive. A reasonable choice for teams that primarily care about reasoning trace access at near-budget pricing.

Lessons for Production Teams

The grok-3-mini → grok-4.3 silent alias redirect on xAI's API is a canonical example of why model name hygiene matters in production systems. There was no API error — just a 4x billing increase starting from the moment the alias went live. Teams that had not set up cost alerting likely discovered the change only at invoice time.

  • 1 Pin specific versioned model IDs, not aliases. If a provider offers a versioned ID (e.g., grok-4.3-20260430), use it instead of the convenience alias (grok-3-mini). Aliases get reassigned; versioned IDs do not.
  • 2 Set up monthly cost alerts. A 4x silent price increase that goes unmonitored for 30 days is a significant budget event. Most cloud billing systems support threshold alerts — use them. Set alerts at 120% of your typical monthly model spend.
  • 3 Subscribe to provider deprecation notifications. OpenRouter, xAI, and most major providers offer email or webhook notifications for model deprecations. These are almost never enabled by default. Find the notification settings and opt in.
  • 4 Maintain a model abstraction layer. Teams with a thin abstraction (a config constant or environment variable for model ID) can migrate in minutes. Teams with model names scattered across ten services across three codebases learn this lesson the hard way.
  • 5 Budget reasoning models have shorter lifespans. The sub-$0.50/1M reasoning tier is highly competitive and providers iterate quickly. Grok 3 Mini lasted less than a year before being absorbed upward. Build for replaceability.
