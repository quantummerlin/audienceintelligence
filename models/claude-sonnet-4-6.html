Extended Thinking — Opt-In, Not Default

⚠ Operational Note — Standard API Behavior

In the standard API completion path, Claude Sonnet 4.6 surfaces zero reasoning tokens. This is by design. The model operates as a direct-response system: your prompt goes in, the answer comes out, with no intermediate thinking chain visible in the response object. For the majority of professional use cases — drafting, analysis, code generation, summarization — this is exactly the right behavior. It keeps latency predictable and cost transparent.

Extended thinking is activated through a separate parameter in the Anthropic API ("thinking": {"type": "enabled", "budget_tokens": N}) or via OpenRouter's include_reasoning: true flag. When enabled, the model exposes its internal reasoning trace before the final answer, which significantly improves performance on multi-step logic, mathematics, and complex planning tasks — at the cost of additional token spend on the thinking trace itself.

The key operational takeaway: do not assume reasoning is happening silently. Standard Claude Sonnet 4.6 completions are direct responses, not reasoning chains. If you need chain-of-thought visible or verifiable, you must explicitly enable extended thinking or embed step-by-step instructions in your system prompt.

## Transformer Attention vs. State Space Models: Architectural Tradeoffs ### Memory Complexity Transformer self-attention computes pairwise token interactions, producing an attention matrix of size O(L²) where L is sequence length. This quadratic memory footprint becomes the binding constraint at scale — a 32K-token sequence requires ~1B attention scores per head before even accounting for KV-cache during inference, which stores key/value projections at O(L × d_model) per layer. SSMs like Mamba operate through a linear recurrence: the hidden state h ∈ ℝ^N is fixed-size regardless of sequence length, giving O(1) memory per recurrence step and O(L) total. Mamba's selective state space parameterization — where Δ, B, C matrices are input-dependent — preserves this bound while adding expressivity, though the discretization overhead introduces modest additional computation. ### Training Parallelism This is where transformers hold a decisive advantage. Because attention is a parallel reduction over the full sequence, backpropagation through attention layers is embarrassingly parallelizable across the L dimension using matrix operations that map cleanly to GPU tensor cores. SSMs face a fundamental tension: their sequential recurrence is inherently serial in the dependency graph. Mamba resolves this via a parallel associative scan (prefix-sum algorithm), reducing recurrence computation to O(log L) sequential steps with O(L) parallel workers. However, the associative scan has higher constant-factor overhead and worse memory access patterns than attention on modern hardware for moderate sequence lengths (L < 8K), making transformers faster in practice on typical training workloads despite worse asymptotic complexity. ### Inference Speed The asymmetry reverses sharply at inference time. Autoregressive transformer generation must read the entire KV-cache each step — O(L) memory bandwidth per token generated — creating a memory-bound bottleneck that worsens as context grows. Mamba's recurrent mode reduces each generation step to a constant-cost state update: O(N × d) operations independent of prior context length. This makes SSM inference latency flat with respect to sequence length, enabling significant throughput advantages at long contexts. Empirically, Mamba demonstrates ~5× higher throughput than similarly-sized transformers at sequence lengths beyond 16K. ### Long-Context Handling Transformers theoretically have perfect recall — any token can attend to any prior token with full fidelity — but practical limitations (quadratic cost, positional encoding degradation) restrict effective context windows even with techniques like RoPE or ALiBi. SSMs compress all history into a fixed-size hidden state, which is fundamentally lossy.
