What Is Grok 4.3?

Grok 4.3 is the standard reasoning entry in xAI's current model family, positioned one tier below the Grok 4.20 flagship and well below the Grok 4.20 Multi-Agent system. The model ID x-ai/grok-4.3-20260430 pins its release to April 30, 2026 — making it the most recently released model in our benchmark cohort.

Within xAI's lineup, the positioning is deliberate. Grok 4.20 ($1.25/$2.50, 2M context) is a pure generation model with no exposed reasoning chain — you get the answer, not the thinking. Grok 4.20 Multi-Agent ($2.00/$6.00, 2M context) is a heavy-reasoning orchestration system with encrypted parallel reasoning chains. Grok 4.3 occupies the middle ground: standard reasoning with a visible summary, at the same input price as Grok 4.20 but with output priced to match, half the context window, and — critically — a reasoning architecture that completes responses efficiently rather than exhausting token budgets.

Text plus image input is supported; file uploads are not. If your workflow requires PDF or document ingestion directly at the API level, you will need to handle extraction externally or route to a model that accepts file inputs, such as Claude Sonnet 4.6. For everything else — technical writing, code analysis, long-context document Q&A, structured reasoning tasks — Grok 4.3's 1M context and $2.50/1M output price make it a compelling default.

Reasoning That Knows When to Stop

The most operationally significant finding from our benchmark is also the simplest to describe: Grok 4.3 returned finish_reason: "stop". Every other model we tested under the same 650 max_tokens ceiling — GPT-5, Claude Sonnet 4.6, Grok 4.20 Multi-Agent, and others — hit finish_reason: "length", truncating their outputs mid-response.

Key Finding — Benchmark Batch

Grok 4.3 is the only model in our six-model benchmark cohort that returned finish_reason: "stop" at max_tokens=650. It completed the full 400–500 word technical analysis with tokens to spare — without being told how many tokens it had available.

The practical implication: applications that treat "length" as a failure mode (parsers expecting complete JSON, structured outputs, step-by-step procedures) will experience fewer silent failures with Grok 4.3 at standard token budgets.

The mechanism behind this is visible in the token breakdown. Of the 1,034 total completion tokens, 473 went to encrypted reasoning and 561 to visible output. That 45.7% reasoning / 54.3% visible split is a notably lean reasoning allocation — especially compared to Grok 4.20 Multi-Agent, which in our testing consumed approximately 75% of completion tokens in reasoning and 25% in visible output. Grok 4.3 thinks just enough and then delivers.

xAI Reasoning Architecture

xAI Reasoning Pattern — Encrypted + Visible Summary

Like Grok 4.20, Grok 4.3 exposes a two-layer reasoning structure. You receive a visible reasoning summary in reasoning_details[0].summary and an encrypted reasoning blob in reasoning_details[1] (format: xai-responses-v1). You can see where the model went — the problem decomposition and scope — but not the step-by-step chain itself.

From our benchmark run, the visible summary read: "The question asks for a detailed technical analysis (400–500 words) on architectural tradeoffs between transformer attention mechanisms and state space models (SSMs) like Mamba. Cover: memory complexity..." — confirming the model correctly parsed the task scope before generating its response.

The self-assessment embedded in the model's final output — "Final answer: 450 words on the architectural tradeoffs covering memory (linear vs quadratic), training (associative scan vs full parallelism), inference (O(1) state vs KV cache), and long-context (native million-token scaling for SSMs)" — is an unusual transparency signal. The model audited its own output and confirmed completion. That pattern does not appear in any other model's response from this batch.

Transformer attention and state-space models (SSMs) such as Mamba represent fundamentally different approaches to sequence modeling, with distinct implications for scaling.

Memory complexity differs sharply. Standard scaled-dot-product attention materializes an n × n matrix (or its block-wise equivalent in FlashAttention), yielding Θ(n²d) bytes of intermediate storage for hidden dimension d. KV-cache growth further adds 2·L·n·d bytes during autoregressive decoding (L layers). In contrast, a selective SSM maintains a fixed-size hidden state whose dimension is independent of sequence length; Mamba's discretization yields an O(d·N) recurrent state (N typically 16), so total activation memory scales linearly as Θ(nd + L·d·N). For contexts beyond 32k tokens this gap exceeds an order of magnitude.

Training parallelism follows from the computation graph. Attention is embarrassingly parallel: all n² dot-products are independent, enabling near-perfect utilization of tensor cores via tiled matrix multiplies. SSMs are expressed as linear recurrences; while a naïve loop is sequential, the associative scan algorithm (as implemented in Mamba's CUDA kernels) computes the prefix sums in O(log n) parallel steps using a parallel prefix-sum primitive. The resulting wall-clock efficiency is typically 3–5× lower than attention at equivalent FLOPs because of irregular memory access and lower arithmetic intensity, although the gap narrows on modern hardware with hardware-aware kernels.

Inference speed exhibits the opposite asymmetry. Per-token generation in transformers requires an O(n) matrix-vector product against the growing KV cache, producing latency that increases with context length. SSMs (and Mamba in particular) perform only a constant-time state update per token after the initial parallel prefix scan, yielding sub-millisecond latency that remains flat even at million-token contexts.

Long-context handling therefore favors SSMs for both training and inference once n ≳ 64k. Transformers require sparse or local attention patterns and still suffer quadratic memory walls without additional compression; Mamba's input-dependent Δ, B, C parameters retain selective recall while preserving linear complexity, enabling end-to-end training on sequences exceeding 1M tokens within the same HBM budget.

The core tradeoff is therefore expressivity versus scalability: attention supplies unrestricted pairwise interactions at quadratic cost, while selective SSMs trade global parallelism for linear-time, constant-state recurrent computation that is markedly more efficient for long-context workloads.
